# VAPS診断サイト仕様書

## 0. この仕様書の位置づけ

本仕様書は、VAPS理論仕様書 `VAPS仕様書v1_09.md` を基準に、VAPS64タイプ性格診断サイトとして実装するための仕様を整理したものである。

- 理論仕様：VAPSの軸、層、タイプ、状態、価値タイプの定義
- 診断仕様：簡易診断・詳細診断・スコア計算・結果判定の仕様
- UI仕様：診断画面、アンケート画面、結果画面の表示仕様
- データ仕様：タイプ、グループ、軸色、グループ色、結果保存形式の仕様

軸定義は理論本文の定義を正とする。

- R：Real / 現実起点
- H：Hypothesis / 仮定起点

したがって、簡易診断の「仮定/パターン/予測/全体像」はH、「事実/差異/具体/精度」はRとして扱う。

## 1. VAPSとは

VAPSは「Value Axis Personality System（価値軸人格体系）」である。

人の価値観と行動傾向を、思考・判断・行動の3層構造で捉える性格モデルであり、MBTI風の分類そのものではなく、自己理解や他者理解のためのコミュニケーションツールとして扱う。

---

## 2. VAPSの全体構造

### 2.1 三層構造

- 思考層：ひらめきから結論まで、どのように思考することを重視するか
- 判断層：正しさの基準から向き合い方まで、どのように判断することを重視するか
- 行動層：現在の生活傾向から将来像まで、どのように生きることを重視するか

### 2.2 各層の側面と軸

| 層 | 側面 | 軸 |
| --- | --- | --- |
| 思考 | 思考起点 | R / H |
| 思考 | 思考構造 | E / A |
| 判断 | 判断起点 | C / P |
| 判断 | 判断原理 | S / F |
| 行動 | 行動運用 | M / G |
| 行動 | 行動志向 | L / O |

---

## 3. 各軸の定義

### 3.1 思考層

#### 思考起点

- R（Real / 現実起点）：現実・観測された情報から思考を始める
- H（Hypothesis / 仮定起点）：仮定・内部モデルから思考を始める

#### 思考構造

- E（Expand / 展開思考）：アイディアの分岐を広げていく
- A（Aggregate / 収束思考）：結論への収束へ向かっていく

### 3.2 判断層

#### 判断起点

- C（Coherence / 整合性起点）：合理性や効率性を基準にする
- P（Priority / 優先度起点）：関係性や優先度を基準にする

#### 判断原理

- S（Stable / 安定的判断）：判断・意見の一貫性を重視する
- F（Fluid / 流動的判断）：判断・意見の柔軟性を重視する

### 3.3 行動層

#### 行動運用

- M（Momentary / 即興運用）：現在は行き当たりばったりで行動している
- G（Guided / 計画運用）：現在は決めた状態で行動している

#### 行動志向

- L（Liberty / 自由志向）：自由な選択を重視する
- O（Order / 管理志向）：一つの選択を重視する

## 4. タイプ生成ロジック

### 4.1 基本ルール

1. 詳細診断の回答から各軸スコアを算出する
2. 各層ごとに優勢軸を決定する
3. 思考・判断・行動の優勢軸を組み合わせてタイプコードを生成する

例：

```text
H > S > O = HSO
```

### 4.2 軸決定の同点処理

優勢軸は以下の順で決定する。

1. 軸スコアの高い軸を採用する
2. 同点の場合は、その層の2つの側面で軸スコア合計が高い側面に属する軸を採用する
3. それでも同点の場合は、簡易診断の自己認識と一致する軸を採用する
4. さらに同点の場合は、簡易診断で選択した側面に属する軸を採用する

### 4.3 タイプコード

タイプコードは3文字で構成する。

- 1文字目：思考層の優勢軸
- 2文字目：判断層の優勢軸
- 3文字目：行動層の優勢軸

## 5. 状態と価値タイプ

### 5.1 価値タイプ

価値タイプとは、本人が自分をどのような人間だと認識しているかを表す指標である。

抽象度の高い簡易診断から算出されるため、理想像や憧れが反映されやすい。価値タイプは詳細診断による実際のタイプと一致することもあれば、異なる結果になることもある。

### 5.2 価値タイプの一致度

- 同一：価値タイプと実際のタイプが一致している状態
- 近似：価値タイプと実際のタイプが2文字一致している状態
- 乖離：価値タイプと実際のタイプの一致が1文字以下の状態

一致度は優劣や良し悪しを示すものではない。理想像、自己認識、環境変化、成長過程によって差が生じる場合がある。

### 5.3 状態

状態とは、その人のタイプを構成する軸がどの程度の精度で使われているかを示す指標である。

- 成熟：軸が安定して使われており、さらに価値タイプと同一である状態
- 安定：タイプ軸は安定して使えているが、自己認識との差異がある場合もある状態
- 経過：すべての軸が完全に安定しているわけではないが、基本的にはそのタイプの傾向が見られる状態
- 不安定：本来のタイプ軸とは異なる軸を多く使っており、軸の使い方に大きな偏りがある状態

状態は、人間としての成熟度や人格の優劣を示すものではない。

### 5.4 状態判定ロジック

- 成熟
  - タイプ軸3つが軸順位の上位3位以内にすべて入っている
  - 価値タイプとの一致度が「同一」である
- 安定
  - タイプ軸3つが軸順位の上位3位以内にすべて入っている
  - 4位の軸と2点以上の差がある
- 経過
  - タイプ軸3つが全体5位以内にすべて入っている
  - 成熟・安定には当てはまらない
- 不安定
  - 成熟・安定・経過のいずれにも当てはまらない

## 8. 診断フロー

### 8.1 基本フロー

```text
診断開始 → 簡易診断 → 詳細診断 → 任意アンケート → 結果表示
```

- 簡易診断と詳細診断は連続して実施する
- 確認画面は設けない
- 戻る操作で前ページに戻れる
- 戻ったページでは前回回答を選択済みとして表示する
- 未回答のまま次へ進むことはできない
- 診断完了後は再診断できる

### 8.2 ページ単位

現在の実装では、1問ごとのページ遷移ではなく、同一セクションの複数問を1ページに表示する。

- 簡易診断：3ページ
  - 思考
  - 判断
  - 行動
- 詳細診断：9ページ
  - 思考起点
  - 思考構造
  - 思考判別
  - 判断起点
  - 判断原理
  - 判断判別
  - 行動運用
  - 行動志向
  - 行動判別

診断中は、回答者に「簡易診断」「詳細診断」「思考起点」などの理論用語を表示しない。

## 9. 簡易診断仕様

### 9.1 目的

簡易診断は、抽象的な質問によって、憧れや理想像を含む自己認知を測る。

簡易診断の回答は、以下に使用する。

- 価値タイプの算出
- 詳細診断の同点処理
- 価値タイプと実際タイプの一致度判定

### 9.2 回答形式

- 2択
- 各層につき、軸選択2問、側面選択1問
- 合計9問

### 9.3 質問一覧

| ID | 質問 | 選択肢 |
| --- | --- | --- |
| SQ1 | 思考はどこから始まる？（思考起点） | 仮定/パターン/予測/全体像（H軸） / 事実/差異/具体/精度（R軸） |
| SQ2 | 思考の進め方は？（思考構造） | 広げていく（E軸） / まとめていく（A軸） |
| SQ3 | どちらを大切にしたい？（側面判定） | 思考を始めること（思考起点） / 思考を進めること（思考構造） |
| SQ4 | 正しさの基準はどっち？（判断起点） | 整合/論理/効率/条件（C軸） / 優先/感情/配慮/事情（P軸） |
| SQ5 | 判断の姿勢は？（判断原理） | 一貫性をもつ（S軸） / 柔軟性をもつ（F軸） |
| SQ6 | どちらを大切にしたい？（側面判定） | 判断の正しさ（判断起点） / 判断の姿勢（判断原理） |
| SQ7 | 日々の過ごし方は？（行動運用） | 状況に合わせて決める（M軸） / 計画を立てて動く（G軸） |
| SQ8 | 今後の生活をどうしていきたい？（行動志向） | その時の気分で行動したい（L軸） / 自分にルールを課したい（O軸） |
| SQ9 | どちらを大切にしたい？（側面判定） | 日々をどう過ごすか（行動運用） / 将来どうなるか（行動志向） |

## 10. 詳細診断仕様

### 10.1 目的

詳細診断は、具体的なシチュエーションに応じた選択によって、実際の価値観や傾向を測る。

### 10.2 回答形式

5段階で回答する。

| 値 | 表示 |
| --- | --- |
| 1 | 同意する |
| 2 | 少し同意する |
| 3 | どちらでもない |
| 4 | あまり同意しない |
| 5 | 同意しない |

UI上は、左を「同意しない」、右を「同意する」として円形スケールで表示する。

### 10.3 配点

#### 通常質問

- 1：該当軸 +5点
- 2：該当軸 +3点
- 3：該当側面の両軸 +1点
- 4：逆軸 +3点
- 5：逆軸 +5点

#### 加点質問

- 1：該当側面の両軸 +3点
- 2：該当側面の両軸 +1点
- 3：加点なし
- 4：逆側面の両軸 +1点
- 5：逆側面の両軸 +3点

### 10.4 質問一覧

詳細診断は39問で構成する。

#### 思考起点（R / H）

1. 何かについて考え始めるとき、実際に見たり聞いたりした情報がないと、考えが動きにくい。（思考起点/R軸）
2. 情報が少ない状態でも、自分で仮定を置いて十分に考えを進められる。（思考起点/H軸）
3. 目の前で起きていることが、思考を強く引き付ける。（思考起点/R軸）
4. 物事や人は、事実を確認する前に内部でモデルにあてはめる。（思考起点/H軸）
5. 経験や具体例がない話だけで、長時間思考を続けられる。（思考起点/H軸）

#### 思考構造（E / A）

6. 結論が出ていない状態でも、複数の可能性を残して考え続けたい。（思考構造/E軸）
7. 考えがまとまったら、多少粗くても一度“結論”として確定させたい。（思考構造/A軸）
8. ひとつの話題から、別の視点や別の案が次々に浮かぶほうだ。（思考構造/E軸）
9. いくつか案が出たら、「判断基準」を決めて取捨選択し、1つに絞りたくなる。（思考構造/A軸）
10. 「まだ決めなくていい」と言われると、むしろ楽になる。（思考構造/E軸）

#### 思考加点

11. 企画を評価するとき、内容の詳細よりも「最初の着想」が光っているかを重視する。（思考加点/起点）
12. 内容が良くても、説明の仕方が整っていなければ説得力は出ないと思う。（思考加点/構造）
13. アイデアが弱いとき、整理し直すよりも、別の発想に変えるほうが早いと思う。（思考加点/起点）

#### 判断起点（C / P）

14. 事情があっても、筋が通っていなければ正しいとは言えないと思う。（判断起点/C軸）
15. 何かを決めるとき、関わっている人の気持ちや事情を優先するべきだ。（判断起点/P軸）
16. 結論が合理的なら、不満があっても仕方のないことだ。（判断起点/C軸）
17. 問題が起きたとき、ケアよりも原因を明らかにしたい。（判断起点/C軸）
18. 誰かを傷つけるなら正しさを選ぶべきではないと思う。（判断起点/P軸）

#### 判断原理（S / F）

19. どんな場合においても、迷わず自分の見解を出せるほうだ。（判断原理/S軸）
20. その場に合わないと感じたら、自分の判断基準をその都度調整することがある。（判断原理/F軸）
21. 正しいと思っていた基準でも、状況が変われば別の基準を使うことに抵抗はない。（判断原理/F軸）
22. 「自分ならこうしたい」という意見は、どんな状況でも伝えたい。（判断原理/S軸）
23. 自分の基準と完全には一致しなくても、場に合うならその判断を選べる。（判断原理/F軸）

#### 判断加点

24. あらゆる基準よりも、自分の選択の仕方を一貫したい。（判断加点/原理）
25. 判断が必要なとき、結論よりも議論や検証をすることが大事だと思う。（判断加点/起点）
26. 自分にとって、何が正しいかよりもどう判断するかのほうが重要だと思う。（判断加点/原理）

#### 行動運用（M / G）

27. 旅行に行くときは、すべての行動を事前に決めておきたい。（行動運用/G軸）
28. 毎日のルーティンをこなせないと、不安になる。（行動運用/G軸）
29. やることがいくつかあるとき、優先順位はその場で決める。（行動運用/M軸）
30. 予定が変わったとき、流れを確認し直したい。（行動運用/G軸）
31. 思いついたことは、準備が整う前にとりあえず始めてみる。（行動運用/M軸）

#### 行動志向（L / O）

32. 目指す将来像になるまでの手段や条件を言語化できる。（行動志向/O軸）
33. あらかじめ方向が決まっているより、選択肢が残されている状態のほうが安心する。（行動志向/L軸）
34. 「この道で行く」と決めると、他の可能性を捨てる感じがして抵抗がある。（行動志向/L軸）
35. 将来像が途中で変わることに問題はないと思う。（行動志向/L軸）
36. 「こうするべき」と決めてしまうと、息苦しく感じることがある。（行動志向/L軸）

#### 行動加点

37. 理想よりも、今をどう生きるかのほうが重要だと思う。（行動加点/運用）
38. 自分が消耗しても、未来のためと思えば頑張れる。（行動加点/志向）
39. 理想の自分になるために行動をしたいと思う。（行動加点/志向）

## 11. 結果ページ仕様

### 11.1 ファーストビュー

表示内容：

- タイプのコア
- タイプコード
- タイプ名
- グループ名
- 状態
- 価値タイプ
- 一致度
- 軸順位
- キャラクター画像

タイプコードとタイプ名は、例 `HSO 教祖` のように表示する。

### 11.2 本文構成

1. 軸ごとの解説
2. 軸バランスグラフ
3. グループ説明
4. 状態・一致度
5. 長所・得意・短所・苦手
6. 向いている役割
7. 相性
8. 共有

### 11.3 軸ごとの解説

- 結果タイプを構成する3軸を円形アイコンとして表示する
- 円の中には軸コードを白文字で表示する
- 円の下に軸名を表示する
- ホバーまたはフォーカスで軸説明を表示する
- 軸色は `lib/vaps-axis-colors.ts` を参照する

### 11.4 軸バランス

- 軸は `R H E A C P S F M G L O` の順で表示する
- 縦棒グラフで表示する
- 数値は非公開
- 各棒の色は軸色を参照する

### 11.5 状態・一致度

- 状態と一致度を大きい文字のバッジで表示する
- ホバーまたはフォーカスで説明を表示する
- 色は `lib/vaps-result-colors.ts` を参照する

### 11.6 長所・得意・短所・苦手

- 4つの窓を横並びで表示する
- 各窓の中に箇条書きで固定文を表示する
- スマホでは2列または1列に折り返す

## 17. 解説生成ルール

- 解説はすべて固定文で管理する
- GPTによる動的生成は行わない
- タイプの解説は、読んだ人が自分の説明をされていると思える文章にする
- 理論の説明や軸定義のみの組み合わせは禁止
- 抽象的な表現を避け、具体的な思想や行動を明示する
- 不快になりすぎない表現にする
- 未検証の仮説段階の傾向は、断定的なタイプ説明には使用しない
- 使用する場合は、軸の矛盾がないことを確認し、一番近い傾向を柔らかく言い換える

結果ページでは以下を組み合わせて表示する。

1. タイプのコア
2. 軸ごとの説明
3. グループの詳細
4. タイプの詳細
5. 状態・価値タイプの説明
6. 長所
7. 短所
8. 向いている職業や役割
9. 相性
